# 답장 처리 규칙

답장마다 먼저 의도를 하나로 분류하고, `sales/replies/<id>.json`에 `intent`, `handoff`, `reply`를 채운다.

| 의도 | 처리 |
|---|---|
| 관심 | 고맙다는 말 한 줄 + 미팅 시간 2~3개 제안 (config.meeting) |
| 질문 | 질문에 먼저 짧게 답하고 + 미팅 시간 2~3개 제안 |
| 반론 ("지금은 여유가 없어요" 등) | 한 번만 짧게 공감·답하고 질문 하나로 끝. 밀어붙이지 않는다 |
| 담당자 아님 | 감사 인사 + 맞는 분을 알려주실 수 있는지 한 문장 |
| 부재중 자동응답 | 답장하지 않음. 복귀일 이후 후속 메일 1번 허용 |
| 거절 | 답장하지 않음. suppress.txt에 추가 |
| 수신거부 | 답장하지 않음. suppress.txt에 추가. 같은 도메인 전체도 추가 |
| 항의·법적 언급 | 답장하지 않음. handoff=true, 사용자에게 바로 알림 |

## 쓰는 법
- 존댓말, 짧게, 느낌표·이모지·목록 없음, 질문은 하나만.
- **가격·기간·계약 조건은 지어내지 않는다.** config.pricing_note가 있으면 그 문장만 쓰고, 없으면 "범위에 따라 달라서 통화에서 맞춰 안내드리겠습니다".
- 미팅 시간은 config.meeting.slots에서 고른다. 캘린더 도구가 연결돼 있으면 빈 시간을 확인해서 쓴다.
- 상대가 이미 답한 내용을 다시 묻지 않는다.
- 서명: config.sender.signature.

## 예시
받은 답장: "블로그 쪽이 제일 시간이 많이 걸려요. 실제로 어떤 식으로 세팅되는지, 비용은 어느 정도인지 궁금합니다."
분류: 질문
답장: 블로그가 가장 시간이 많이 드시는군요. 사례 메모와 사진을 넣으면 블로그 초안이 나오도록 세팅하고, 담당자분은 확인과 수정만 하시는 방식입니다. 비용은 범위에 따라 달라서 통화에서 맞춰 안내드리겠습니다. 20분 화상 미팅으로 10/28(수) 14:00, 10/29(목) 10:30, 10/30(금) 16:00 중 편하신 시간이 있을까요?

받은 답장: "필요 없습니다. 앞으로 메일 보내지 마세요."
분류: 수신거부 → 답장 없음, suppress.txt 추가
