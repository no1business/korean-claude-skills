# yt-package

모든 결과물은 한국어로 쓴다. 한국 유튜브 시청자 기준으로 쓰고, 영어 예시는 한국 상황으로 바꾼다.

제목과 썸네일은 하나의 단위다. 따로 쓰는 게 패키징이 실패하는 가장 흔한 이유다. 썸네일이
제목을 반복하면, 클릭을 부르는 면적의 절반이 같은 말을 두 번 하게 된다.

```bash
python3 title.py --title "..." --thumb "AI가 다 함"
python3 title.py titles.txt            # one per line, ranked
```

## 쓰기 전에

1. `~/.claude/youtube/voice.md`가 있으면 읽는다. 사용자의 말투 프로필이다. 카메라 앞에서 어떻게
   말하는지, 절대 안 쓰는 말, 누구에게 말하는지, 무엇은 주장하지 않는지가 들어 있다. 파일이
   없으면 **사용자 본인의 영상 세 개**를 달라고 한다. 읽거나 받아 적어서 말투를 파악하고 파일을
   쓴다. 말투가 틀린 대본은 대본이 없는 것보다 나쁘다. 사용자가 그걸 소리 내어 읽어야 하기
   때문이다.
2. 숫자, 성과, 출처를 절대 지어내지 않는다. 숫자가 있으면 더 좋아질 문장인데 숫자가 없으면,
   사용자에게 물어보거나 숫자 없이 쓴다.

## 도구가 지키게 하는 규칙과 이유

- **60자**에서 데스크톱 검색 결과가 잘리고, **40자**에서 모바일 홈 피드가 잘린다. 둘 다 보고하는
  이유는 잘리는 방식이 달라서다. 데스크톱은 끝부분을 잃고, 모바일은 주어를 잃을 수 있다.
  한글은 영문보다 글자 폭이 넓어서 title.py는 한글 1자를 영문 약 2자로 계산한다. 한글만 쓰면
  데스크톱 약 30자, 모바일 약 20자 안쪽이 안전하다.
- **썸네일은 제목을 반복하지 않는다.** 다른 말로, 같은 약속을 한다.
- **썸네일 문구는 최대 세 단어.** 피드 크기에서 네 번째 단어는 회색 얼룩이 된다.
- **숫자, 이름, 날짜** 하나가 어떤 형용사보다 낫다.
- **영문 대문자 단어는 두 개까지.** 그 이상이면 제목이 스팸처럼 읽힌다.

## 열 개 쓰고 두 개 남긴다

제목을 열 개 만들고 전부 `title.py`에 돌린다. 상위 세 개를 점수와 각각의 구체적인 문제점과 함께
사용자에게 보여 준다. 1등 제목에는 썸네일 브리프를 쓴다. 표정, 구도, 세 단어, 그리고 피드
크기에서 대비가 유지되려면 배경이 어떠해야 하는지.

## 마지막 관문

여기서는 아무것도 게시되지 않는다. 이 스킬은 쓰기만 하고, 게시는 사용자가 한다. 모든 결과물은
사용자가 복사할 수 있는 블록으로 끝나고, 매번 마지막 줄은 이 질문이다: **이대로 올릴까요, 고칠까요?**
